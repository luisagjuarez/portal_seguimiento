# Bitácora — 2026-08-25

## Migración del frontend de "landing page" (estado) a Portal con rutas reales

El usuario notó que el portal era efectivamente una landing page de una sola pantalla: toda la
navegación (`App.jsx`) se manejaba con un único `useState("inicio")` (`pagina`) que decidía qué
componente renderizar. No había URLs reales por pantalla — la barra de direcciones siempre
mostraba `/`, no había historial de navegador (atrás/adelante no funcionaban), no se podía
compartir un link directo a una solicitud o tarea, y refrescar la página (F5) siempre volvía a
"Inicio". Pidió convertirlo en un portal con rutas de verdad. Trabajado en modo plan; plan
completo en `/home/lg/.claude/plans/quirky-watching-boole.md`.

**Enfoque:** se agregó `react-router-dom` (`^6.26.2`, única dependencia nueva) con
`BrowserRouter` en `main.jsx` y estas rutas en `App.jsx`:

| Ruta | Página |
|---|---|
| `/` | `InicioPage` |
| `/chat` | `ChatWindow` |
| `/solicitudes` | `SolicitudesPage` (listado) |
| `/solicitudes/:id` | `SolicitudDetallePage` |
| `/tablero` | `TableroPage` |
| `/tareas/:id` | `TareaDetallePage` |
| `/usuarios` | `UsuariosPage` (solo Scrum Master, si no `<Navigate to="/" replace />`) |
| `/cambiar-password` | `CambiarPasswordFormulario` (autoservicio) |
| `*` | `<Navigate to="/" replace />` |

No hizo falta tocar `nginx.conf` (ya tenía el fallback SPA correcto,
`try_files $uri $uri/ /index.html`) ni `vite.config.js` — confirmado por `curl` que rutas
profundas (`/solicitudes/999`, `/tareas/1`) devuelven `200` con `index.html` tanto en el dev
server de Vite como en producción vía nginx.

**Decisiones tomadas durante el plan (sin bloquear en preguntas triviales):**
- El link de recuperación de contraseña sigue apuntando a `{FRONTEND_ORIGIN}/?reset_token=...`
  (sin tocar el backend/`mailer.py`): la detección de `reset_token` en query string se quedó
  como gate global en `App.jsx`, independiente de la ruta activa.
- El login y la pantalla obligatoria de cambio de contraseña se siguen renderizando **inline**
  (sin URL `/login` propia) cuando no hay `usuarioActual` o `debe_cambiar_password` es `true` —
  mismo comportamiento visual que antes, ahora dentro del árbol de rutas.
- Se eliminó el estado `origenTarea` (antes usado para que "Regresar" desde el detalle de
  tarea supiera si volver a la solicitud o al tablero). Con rutas reales, `TareaDetallePage`
  simplificó su botón "Regresar" a navegar siempre a la solicitud padre
  (`/solicitudes/${tarea.solicitud_id}`, o `/tablero` como fallback si aún no cargó la tarea)
  — simplificación limpia habilitada por el router, sin cambio de comportamiento visible para
  el caso más común.
- `SolicitudDetallePage` → "Regresar" navega explícitamente a `/solicitudes` (no
  `navigate(-1)`), para que el destino sea predecible incluso si se llegó por link directo.

**Archivos modificados:**
- `frontend/package.json` — nueva dependencia.
- `frontend/src/main.jsx` — `<App/>` envuelto en `<BrowserRouter>`.
- `frontend/src/App.jsx` — reescrito: se eliminaron `pagina`/`solicitudSeleccionadaId`/
  `tareaSeleccionadaId`/`origenTarea` y todos sus handlers; el "contenido normal" (post-login,
  post-cambio-obligatorio-de-password) pasó a ser un `<Routes>`; `pantallaCentrada` ahora usa
  `useLocation()` en vez de comparar `pagina`.
- `frontend/src/components/Sidebar.jsx` — reescrito con `<NavLink>` (resalta activo por URL en
  vez de por prop `paginaActual`); ya no recibe `paginaActual`/`onCambiarPagina`.
- `frontend/src/components/InicioPage.jsx`, `SolicitudesPage.jsx`, `TableroPage.jsx`,
  `SolicitudDetallePage.jsx`, `TareaDetallePage.jsx` — cada uno perdió sus props de navegación
  (`onIrA`, `onVerDetalle`, `onVerTarea`, `onRegresar`, `onVerSolicitud`) y ahora usa
  `useNavigate()`/`useParams()` internamente. `esScrumMaster` se sigue pasando como prop a
  `SolicitudDetallePage` (se deriva de `usuarioActual` en `App.jsx`, no se puede sacar de la
  URL).
- `frontend/src/components/CambiarPasswordFormulario.jsx` — sin cambio de props; solo cambió
  qué le pasa el *caller* en el uso autoservicio (`onCambiada`/`onCancelar` → `navigate("/")`).
- `frontend/src/styles.css` — `.sidebar button` → `.sidebar a` (el `NavLink` renderiza un
  `<a>`, no un `<button>`; se le agregó explícitamente `display:block`, `padding`,
  `text-decoration:none`, `cursor:pointer` que antes venían gratis del selector global
  `button`).

No hizo falta tocar `ChatWindow.jsx`, `UsuariosPage.jsx`, `SolicitudCard.jsx`,
`LoginPage.jsx`, `ResetPasswordPage.jsx`, `nginx.conf`, `vite.config.js`, `Dockerfile`, ni el
backend.
